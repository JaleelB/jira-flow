# JiraFlow v0.5 Hook Signatures

The migration catalog is derived from tag `v0.5.0`:

- `internal/git.go::generateHookScript` wrote exactly `#!/bin/sh`, a newline, the resolved `commitmsg` or `postco` helper path, one space, and `"$@"`, with no trailing newline.
- `internal/status.go::InstallHooks` could instead create a symlink to the resolved `commitmsg` or `postco` helper.
- v0.5 overwrote entire hook files. It did not emit a managed block that can be safely removed from mixed content.
- `internal/config.go` created configuration in process memory only. Manual issue/mode state was not durable.

The v1 migrator therefore recognizes only the exact anchored wrapper with the hook-appropriate helper basename, or the hook-appropriate helper symlink. Added lines, shell operators, a different helper, an ordinary foreign hook, or a non-file hook path are ambiguous and block all migration mutation.

An eligible migration removes only recognized artifacts, installs the v1 owned `commit-msg` integration, removes recognized legacy `post-checkout`, and writes `enabled=true`, `mode=hybrid`. It never invents Manual state.
